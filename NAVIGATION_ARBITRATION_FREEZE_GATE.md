A map generated by the last submitter was covered by the old confirmation dialog, and attempted underlying tab clicks were not accepted. Such blocked clicks are now explicitly excluded from coverage.

## Root Cause

Navigation root cause:
- Snapshot failure: the error path stops before registering tabs and the polling fragment, leaving no case-level recovery control. The keyed tab can also be cleaned up when omitted.
- Map-generation hang: map completion and failure marking originally occurred after the spinner context exited. Streamlit 1.62 spinner cleanup enqueues a UI message; pending execution-control requests can interrupt there. A completed model response, or its failure, is then lost before the reservation is settled. The existing empty reservation prevents another automatic generation.

Local implementation evidence: installed Streamlit spinner.py finally calls enqueue_message(clear_transient()); ScriptRunner checks pending execution-control requests when enqueuing. Browser traces independently show the model returned followed by an interrupted run with zero completion calls.

Arbitration root cause: UNKNOWN for the reported production failure. Its successful final persistence already occurs inside the spinner; the map-specific ordering defect must not be presented as its proven root cause.
Shared root cause: UNPROVEN.

Important mismatch: the reproduced snapshot failure has a visible error; the map hang retains the tab group. Neither completely matches “only title and A/B submitted badges remain.” Existing orphaned reservations are not repaired by this preventive patch.
