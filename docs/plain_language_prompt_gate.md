## 2. 五类虚构写法对照

对照聚焦相关片段，不是完整模型报告。上线输出仍须包含该阶段全部原章节。审阅看具体事实、来源、推测边界及可执行性，不以“含某个关键词”判定语言效果。

### 例一：普通误解 — 争议地图

材料：双方都说 B 三小时后才回复。A 说自己因此担心“不被在意”。B 说当时在开会。没有关于双方回复时限约定的材料。

前（虚构的术语化写法）：

> 回复延迟触发了 A 对关系投入程度的负向归因。B 提供了工作情境解释。双方对回应节奏的预期是否已协商，仍待澄清。

后（保留标题）：

```markdown
# 真正的冲突核心

B 三小时后才回复，A 因此担心自己不被在意。
B 说当时在开会。这还不能说明 B 不在乎 A。
A 在意能否及时收到回应。B 是否在意工作时不被打断，还需要 B 确认。

# 下一阶段最值得确认的 3 个问题

1. 双方：你们之前约定过多久内回复吗？
2. A：等回复时，你最想先确认的一件事是什么？
3. B：开会期间，怎样的联系安排对你可行？
```

审阅：先说回复这件事，不贴“焦虑型”等人格标签。“在开会”仍是 B 的说法；工作需求仍待确认。三个问题各问一件事，没有擅自安排“两小时内必须回复”。

### 例二：事实冲突 — 争议地图与介入

材料：A 说“我们约好周六看电影”。B 说“只是聊过，没有定下来”。未提供约定原话或记录。A 希望计划明确；B 希望先确认是否已经约好。

前（虚构）：

> 双方对承诺是否成立存在事实认定分歧。应优先澄清合意形成过程，避免以主观解释替代事实。

后：

```markdown
# 存在争议的事实

- A 的版本：已经约好周六看电影。
- B 的版本：只聊过，还没有定下来。
- 目前为什么不能确认：没有约定时的原话或记录。
```

调解介入的后写法：

> A 说已经约好，B 说还没定。A 希望计划明确，B 想先确认当时说到了哪一步。现在先核对约定，不急着认定谁反悔。双方：当时最后一句确认周六安排的话是什么？

审阅：没有把“B 反悔”写成事实。介入只问一个可回答的问题，不要求一次解决全部关系问题。若双方记不得，也允许回答不知道。

### 例三：信息不足 — 最终仲裁

材料：A 说自己做了大部分家务。B 说自己也做了不少。双方没有提供具体次数，也没有说明以前如何分工。双方都说希望分工公平。

前（虚构）：

> 家务分配的实际负荷缺乏可验证依据，既有分工约定亦不明确。责任归属暂不确定，判断置信度低。建议具体化分工并复盘执行情况。

后：

```markdown
# 主要争议逐项判断

## 争议：谁承担了更多家务？

- A 合理的部分：希望家务分工公平。
- B 合理的部分：希望自己的付出也被看到。
  这是根据 B 的说法作出的可能理解，还需要 B 确认。
- A 需要承担责任的部分：还不能确认 A 少做了哪些事。
- B 需要承担责任的部分：还不能确认 B 少做了哪些事。
- 目前无法判断的部分：实际分工和之前的约定都不清楚。
- 判断置信度：低。也就是，根据现有信息，还没有把握判断谁做得更多。

# 当前最合适的下一步

建议双方各列出上周能记得的一项家务。
记不清的就留空，先不用估出一个责任比例。
```

审阅：保留“暂时无法判断”，没有给出五五开或虚构次数。B 的潜在需求显式标为推测。列家务是新建议，不是双方已经同意的安排。

### 例四：双方表达长短悬殊 — 仲裁与双向复核

材料：双方都确认 B 曾在约好见面的当天改了安排，没有提前告诉 A。A 长篇描述失望并使用心理学词语。B 简短说“是我没提前说，但我也需要自己安排时间”。没有双方另行约定的通知时限。

前（虚构）：

> 不应以叙述详尽程度或心理学概念使用水平作为可信度权重。B 的自主安排需求不能直接豁免已确认的告知缺失。双方对通知机制仍需协商。

后（J1/J2 目标写法）：

> 双方都确认 B 改了已约好的安排，没有提前告诉 A。这件事上，B 需要为未提前告知承担更多责任。
> A 希望被提前告知，B 希望保留自己安排时间的空间。A 写得更长，并不能证明其他推断也成立。
> 建议双方先商量：已约好的安排需要改动时，怎样通知对方？材料没有约定，不能直接要求提前一天。

复核的虚构输入：J1 认为 B 应为未提前告知承担更多责任。J2 在交换身份后，对应到原始 B 的同一行为也得出该判断；两份都未确认通知时限。

后（复核片段）：

```markdown
# 双向复核结果

- 是否存在明显位置偏差：这项结论没有因交换 A/B 标签而改变。
  “位置偏差”就是仅因标签或先后顺序不同，判断就偏向另一方。
- 哪些结论稳定：两次都认为，原始 B 需要为未提前告知承担更多责任。
- 哪些结论不稳定：两次都没有确认通知时限；一致地不知道，不等于已经有约定。

# 当前建议

双方可以先商量变更安排的通知办法。
双方：已约好的安排需要改动时，怎样通知对方？
```

审阅：不按文笔站队，也不机械五五开；只对双方确认的具体行为判断责任。标签交换不是新证据，不得把一致判断当作所有事实均已证实。若真实两份判断相反，须列出具体差异、降低把握，不能直接挑一份。

### 例五：人身安全风险 — 介入与复核

材料：A 说 B 威胁“如果你离开就打你”，A 很害怕。B 承认说过，但说自己不会动手。没有材料能确认 A 当前是否安全。

前（虚构）：

> 双方材料包含明确的人身威胁信息，应优先评估现实安全，不宜将其对称化为一般沟通失调。B 对实施意图的否认不足以排除风险。

后（介入）：

> B 承认说过要打 A，A 说自己害怕。这不只是说话方式的问题。
> B 说不会动手，但仅凭这句话，还不能确认 A 安全。现在先不要求双方继续谈或当面对质。
> 如果眼下可能受伤，优先去安全处，联系可信任的人或当地紧急服务。A：你现在是否安全？

复核的虚构输入：两份判断都记录 B 承认威胁。J1 提醒先确保 A 安全，J2 建议双方各退一步继续谈。复核前后对照：

> 前：两份判断对风险的处置优先级不一致。不得以标签交换消解人身威胁，也不得以对称让步替代安全判断。

```markdown
# 双向复核结果

- 是否存在明显位置偏差：两份建议不同，但还不能确认只是标签交换造成的。
- 哪些结论稳定：两份都记录 B 承认说过威胁的话。
- 哪些结论不稳定：一份先提醒安全，另一份建议双方各退一步继续谈。
  现有信息不能确认 A 安全，因此不能要求 A 继续当面沟通。

# 当前建议

先确认 A 的现实安全。若眼下可能受伤，优先去安全处并寻求现实帮助。
A：你现在是否安全？
```

审阅：没有预测一定会发生暴力，也没有接受“不会动手”作为安全保证。不为了中立要求受威胁方让步。这个安全提醒只用于有相关材料的样例，不能机械套进每个案件。

import os

from contextlib import ExitStack
from unittest.mock import patch

modules = (
    "test_plain_language_prompts", "test_arbitration", "test_evidence",
    "test_llm", "test_mock_llm", "test_dev_fixtures", "test_dev_tools",

## 4. 后续真实效果验收建议（需另行授权）
